# ADR 0009: Reachability limited to Norway and operator egress; every endpoint behind Entra ID

Date: 2026-10-20
Status: Accepted

## Context

An audit on 2026-10-20 of everything reachable from the Internet:

| Endpoint | Reachable from | Authentication | Verdict |
|---|---|---|---|
| Ingress LB `57.174.156.100` :80/:443 (podinfo, Tekton Dashboard) | anywhere (NSG `Internet`) | podinfo: none (demo); Tekton Dashboard: **none** (read-only) | fix |
| Argo CD | not published (ClusterIP); `kubectl port-forward` only | `admin` with rotated password, no anonymous, RBAC default deny, TLS | ok |
| AKS API server (public FQDN) | anywhere | Entra ID + Azure RBAC; local accounts still enabled for bootstrap | narrow |
| ACR `acrmadbadgerbadger` | anywhere | Entra ID only, admin user off, no anonymous pull | Basic SKU has no firewall |
| State storage account | anywhere | Entra ID only, shared keys off, HTTPS, TLS 1.2 | narrow |
| Azure Monitor workspace, Automation account | anywhere | Entra ID / managed identity, local auth off | no IP firewall without Private Link |

Nothing exposed a password-less login except the Tekton Dashboard, which has no login at
all. The owner wants every service authenticated and no traffic from outside Norway.

## Decision

1. **Country allowlist on the ingress NSG.** `live/azure/poc/allowlist/no-ipv4.txt` holds
   every IPv4 prefix registered to Norway (RIPE/NRO delegated statistics via RIPEstat,
   1337 allocations collapsed to 1241 prefixes), generated by `scripts/country-prefixes.py`
   and refreshed with `make allowlist-refresh`. `10-network` feeds it, plus
   `trusted-egress-ipv4.txt`, into one NSG rule (`source_address_prefixes`, limit 4000) for
   ports 80/443. Everything else hits `DenyAllInBound`. Works because the AKS load balancer
   uses floating IP, so the NSG sees the real client address.
2. **Registration is not location.** The operators reach Azure through Zscaler's Oslo
   datacenters, whose ranges are registered to Switzerland. `trusted-egress-ipv4.txt`
   lists them (8 × /23 from `config.zscaler.com`) and is added everywhere the country list
   is used or does not fit.
3. **API server and state storage: operator egress only.** Both accept at most 200 ranges,
   so they get `trusted-egress-ipv4.txt` (+ per-stack `*_extra_sources`), not the country
   list. `api_server_restricted` / `storage_restricted` default to `true`. ARM operations
   are unaffected, so a lockout is always recoverable with `az` (see README).
4. **No unauthenticated service through the ingress.** The Tekton Dashboard ingress is
   removed; it is reached via `kubectl port-forward`, like Argo CD, which means Entra ID
   first. podinfo stays as the public reference app behind the country filter.
5. **Not done, and why.** ACR Basic cannot filter IPs (Premium is ~$50/month); the Monitor
   workspace and Automation account would need Private Link; both are Entra-only and stay
   open. Geo-blocking by real location (Front Door / App Gateway WAF, ~$35–250/month) is
   out of proportion for a POC. No TLS on the nip.io hosts yet, so no password prompts are
   added at the ingress; put SSO (oauth2-proxy + Entra ID) in front of any dashboard that
   must be public.

## Consequences

- From outside Norway, or from a Zscaler datacenter other than Oslo, the ingress, the
  API server and the state backend time out. Recovery commands are in the README.
- Country lists drift. Refresh monthly; the diff is reviewable. The refresh writes through
  a temp file and refuses implausible results, and an empty allowlist fails the plan
  instead of reopening the ports (`ingress_allow_internet` is the only way to reopen).
- Non-Norwegian callers that must reach the ingress need `ingress_extra_sources`: Let's
  Encrypt HTTP-01 validators (prefer DNS-01 when a DNS zone exists), GitHub webhooks for
  Tekton triggers, external uptime checks.
- The cluster's own outbound IP is kept in the API server allowlist (read from the node
  resource group's load balancer) so in-cluster controllers never lose the API.
- One NSG rule with ~1250 prefixes replaces two single-source rules; applying it drops
  the allow rule for a few seconds.
- `local_account_disabled` remains `false` for the GitOps bootstrap. Flip it once
  `30-gitops` can use Entra ID credentials.
